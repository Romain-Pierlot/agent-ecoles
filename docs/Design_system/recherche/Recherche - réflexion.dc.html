Réflexion produit · Porte 2 « Chercher »
Recherche — mécanisme & contenu
Le bloc de recherche est transverse : il vit dans plusieurs pages (accueil, hub Explorer, en-tête des pages internes). Ce document pose ce qu'on peut y chercher, comment l'autocomplétion réagit, et ce que contient la page /recherche.
1 · Le parti pris — deux portes, deux intentions
La recherche ne doit pas essayer d'être une mini-Camille. On sépare nettement l'intention pour que chaque porte reste lisible.
Chercher — la recherche
OÙ & QUEL
Accès direct à une destination qu'on connaît déjà : un nom d'établissement, une ville, un code postal, un département. « Je sais ce que je cherche, emmène-moi. »

LEQUEL, POUR MOI
Le choix selon des critères et des arbitrages : chorale, allemand LV1, pas trop loin, bonne valeur ajoutée. « Aide-moi à décider. » — c'est une conversation, pas une requête.
un collège avec chorale pas trop loin
La règle V1 — volontairement simple : la recherche route vers une FICHE (nom de collège) ou un LIEU (ville, CP, département, région). C'est tout. Les CRITÈRES (options, langues, dispositifs, notation) deviennent des filtres sur la page de résultats. Camille reste la porte conversationnelle, à part.
2 · Que peut-on taper ? — types de requête → destination
Deux familles seulement en V1 : un nom d'établissement, ou un lieu. On détecte le type par des heuristiques simples (regex CP, correspondance base villes / établissements) puis on route. Un seul champ.

3 · Le bloc de recherche transverse — une seule densité, partout
Un seul composant, une seule taille, identique partout : accueil (bande sous le héros Camille), hub Explorer (héros de la page), en-tête des pages internes (région / département / ville) et haut de la page de résultats. Pas de version réduite — le bloc garde la même présence sur toutes les pages.

Q1 · Filtres exhaustifs
Les filtres se cumulent (ET) et un compteur live suit chaque changement. Pour éviter les impasses : on grïse les valeurs qui mèneraient à 0 résultat. Si 0 malgré tout → état vide : retirer le dernier filtre / tout réinitialiser. Filtres actifs en puces détachables au-dessus de la liste.
Q2 · Tris — deux listes, deux tris
Établissements : Notation (défaut) · Réussite brevet · Distance (si adresse saisie) · Nom A→Z. Communes : Nom A→Z (défaut) · Nombre de collèges · Proximité (si adresse). Le A→Z est le repli sûr quand aucune métrique ne s'impose — indispensable sur une requête courte qui remonte beaucoup de communes.
Q3 · Tags & le « +N »
Statut d'abord (Public / Privé), puis 2 tags max dans un ordre de priorité fixe (prioritaire > dispositif > section/langue > option). Le « +N » est cliquable : il déplie les tags restants dans la carte (et tooltip au survol) — jamais une nouvelle page. Couleurs par famille : statut vert, prioritaire ambre, dispositifs & sections bleu.
Décisions tranchées (V1) : (1) filtres au lancement — Public/Privé, Dispositifs, Sections & langues, Notation min. (4 chips, voir README hi-fi — pas de catégorie "Options & activités" séparée). (2) un lieu unique route direct vers sa page (nom → fiche, ville/CP → page ville, dépt/région → maillage). (3) autocomplétion : max 4 suggestions par groupe. (4) « adresse → collège de secteur » confirmé hors scope V1.
